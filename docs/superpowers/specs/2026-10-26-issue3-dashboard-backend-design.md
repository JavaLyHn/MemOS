## 方案与取舍

### 采用：独立 FastAPI 后端 + SQLite

浏览器经现有 Vite 同源代理访问控制台后端；控制台后端通过 MemOS REST 访问记忆、知识库和 Prompt，通过 SQLite 管理控制面与审计查询索引。

选择由实现者提出：复用 D:/MemOS/.venv 的 FastAPI、httpx、pytest 依赖和现有 Python 服务经验；SQLite 使用标准库，避免为本地及单实例交付再部署数据库。SQLite 开启 foreign_keys、WAL、busy_timeout，事务保护成员与账号约束。

代价：多一个轻量进程；SQLite 的单机写入能力是明确部署边界。后续多副本部署需要共享控制面数据库和集中日志摄取，不声称本方案天然支持多实例。

### 未采用：直接扩展 MemOS 为完整管理后台

可以少一个进程，但账号、邀请、审计索引与记忆服务初始化耦合，测试容易依赖数据库和模型。仅在上游缺少必要能力时补最小接口/语义，不将整个控制面塞入 MemOS。

### 未采用：直接查询 Neo4j/Qdrant 实现整个控制台

查询自由，但耦合内部 schema，尤其删除容易造成图、向量状态不一致。默认通过 REST；能力缺口在上游解决。

## 身份与权限

- 使用后端会话 Cookie；新增后端自己的 /__login、/__logout 页面，不修改 React 前端。Vite 已具备相应代理。
- bootstrap 管理员通过本地一次性初始化命令创建，密码使用带盐 scrypt 哈希；不硬编码公开默认密码，也不把任意浏览器默认当管理员。
- 会话使用随机 token，服务端仅保存摘要、账号、到期时间；Cookie HttpOnly、SameSite=Lax，生产 HTTPS 开启 Secure。
- 写请求检查 Origin/CSRF；登录/邀请页表单提供 CSRF token，同源 API 按允许的控制台 Origin 校验。
- 管理员可维护账号；owner/管理员管理项目成员与邀请；editor 允许项目内写操作；viewer 只读。
- 邀请仅创建时返回明文 token，数据库保存摘要；原子校验过期、撤销、已使用状态。
- 管理操作不能移除/降级最后一个 owner 或最后一个有效平台管理员；禁用账号立即使其会话失效。
- 邀请落地与账号创建由后端页面/初始化 CLI 提供，避免依赖前端不存在的注册界面。
- 账号删除为有约束的控制面操作：个人空间和成员关系按契约处理；团队密钥/邀请只清空创建者，不误删团队资源。

## 接口契约

- 逐 method + path 登记，不能仅统计 URL 路径数量。实施时生成 60 操作能力矩阵并建立显式路由覆盖测试。
- 成功统一 code=0；上游成功 code=200 必须适配。失败统一 code/data/message，并返回合理 HTTP 状态。
- 检查上游 HTTP、JSON 格式、业务 code 以及 data.status=failed/failure 或 success=false，不把业务失败包装成成功。
- 保留 records / logs / memListItemResponseList / list 四种列表键；分页、总数和模板分页附加字段按具体 schema。
- 分页从 1 开始；默认值按各操作定义；正整数和有限最大页大小统一校验。账号列表保留实际 page/pageSize，其余使用各接口规定的 pageNum/pageSize。
- 所有日期明确 UTC/RFC3339；日汇总使用文档化的 Asia/Shanghai 时区，先转换边界再过滤 UTC 时间。
- 日志 requestBody/responseBody 是 JSON 字符串；历史记录已是字符串时不二次编码。
- scope、projectId、删除参数等实际消费字段与 spec 的缺漏，先在 openapi.json 补齐，再实现；不对 src/ 打补丁。
- 不实现通配路由“所有未知请求都返回成功”；未启用功能返回明确的非零错误。

## 记忆列表、详情、筛选与删除

### 类型和查询

- 支持 text_mem、pref_mem、event_mem、profile_mem、skill_mem、tool_mem 六个标签。
- 事实类映射 WorkingMemory / LongTermMemory / UserMemory / OuterMemory；偏好 PreferenceMemory；技能 SkillMemory；工具 ToolSchemaMemory / ToolTrajectoryMemory。
- 事件类根据当前上游 EventMemory 与旧类型兼容情况验证，不能只按旧截图假设 Context/InsightMemory；画像通过上游 profile 实例能力获取，不能伪造为普通事实。
- 项目条件在发给上游前确定，所有列表/详情/删除都限定同一 upstream_cube_id。
- 详情请求没有 projectId 时使用当前账号已选项目并检查资源归属，不能凭 ID 跨租户读取。
- 先筛选，再计算 total，再分页；不能先拿上游第一页再本地过滤，造成假总数或漏页。
- 默认口径仅 activated。明确排除 archived/deleted；对 resolving/frozen/expired 不偷偷混算。上游缺少组合过滤时优先补查询能力。
- 搜索按接口的内容检索语义实现，不能把 top_k 向量检索当作全量分页列表。
- 集中白名单投影 memoryId、memoryContent、subjectType、externalUserId、createTime 及类型专有字段；剔除 embedding、sources、history。长正文设置明确投影限额，详情按需返回；10 条列表总响应必须 <200KB。

### 删除语义需要的最小上游修正

当前上游按 ID 删除会物理删除，而 Issue 同时要求软删除、恢复和普通 REST 查不到。这三项不能靠 Dashboard 本地隐藏一条记录满足。

拟定行为：

1. 新增上游受控 POST /product/transition_memory，参数为 mem_cube_id、memory_id、target_status（deleted 或恢复为原状态）、operation_id。不改变现有硬删除接口，也不假设现有 update_memory 提供可靠的图/向量原子更新。
2. Dashboard 删除先校验全部目标属于当前项目和标签，再请求上游变更状态，逐项记录结果；部分失败不能假装全部成功。
3. 上游普通单条、多条读取和相关列表/图谱/检索不暴露 deleted；存储中仍保留记录。
4. 通过同一受控操作恢复到删除前状态；上游记录 previous_status。冻结记忆遵循现有生命周期限制，不能绕过；本阶段普通页面只能删除 activated 条目。
5. Dashboard operation_records 保存操作 ID、目标与结果用于查询；上游使用现有 MetadataStore 的新 document kind 保存生命周期意图与重试进度，负责恢复，不依赖 Dashboard 存储作为记忆真相。

### 图与向量同步确认（不能直接沿用现有 best-effort 行为）

源码 Neo4j.update_node 会先提交图，再尝试同步向量；同步异常仅记 warning。因此受控 transition 操作必须自行确认状态，不能将 update_node 返回视为操作成功。

- 先持久化幂等的生命周期意图，再进行图状态更新、向量 payload 更新和双边读回确认。意图包含租户、记忆 ID、原状态、目标状态和阶段，不包含向量或完整正文。
- 意图使用现有上游 CloudEntity 元数据文档存储，不新建业务记忆副本。写入意图失败则不开始修改；同一 operation_id 重放返回当前进度。
- 当向量点不存在时，只有明确确认该记忆本来未被索引，才允许作为无向量记录处理；Qdrant 连接失败或读取失败不等价于不存在。
- 确认 graph.status 与存在的 vector.payload.status 都为目标值后，才返回业务成功。否则返回明确的可重试失败及 operation_id，不把部分写入当成功。
- 上游后台任务在启动时和运行期间重试未完成意图，按 ID 与租户检查当前状态；同一记忆的并发生命周期操作串行化，不用盲目回滚覆盖后续修改。
- 普通检索的最终结果按图中当前状态再次过滤；图库不可用时返回错误，不能透传可能已被删除的旧向量命中。因此向量补偿期间也不会继续展示已删除记忆。
- 恢复也经过相同确认和重试；deleted 意图尚未完成时，恢复操作先串行解决前一操作。意图的原状态保存在上游，Dashboard 重建不会丢失恢复依据。
- 测试必须注入 Qdrant 不可用、图更新后进程中断、重复 operation_id、相反操作并发和服务重启，证明没有假成功、没有删除后再召回。

### 画像标签单独处理

画像条目不是普通 Memory 图节点。ProfileService.recall 将实例 fields 的各个叶子字段合成为 instance_id + path 的行，现有接口还要求显式 user_id 或 agent_id。因此不能让画像标签落入普通记忆 ID 查询或更新逻辑。

- 新增上游受租户约束的 POST /product/list_profile_memories、POST /product/get_profile_memory、POST /product/transition_profile_memory。列表允许项目内所有主体，并支持 subject_type/subject_id、内容、时间过滤和分页；不能要求控制台先知道每个主体 ID。
- 复用现有 profile_instance 文档。每个字段增加 status、deleted_at、previous_status；删除保留 value，只改字段状态，不删除整个实例、不改其他字段。
- 字段身份由上游按 instance_id 和 profile_path 解析并检查归属，沿用现有行 ID；不允许后端通过不可靠的字符串拆分猜主体和字段。
- 单条详情、项目级枚举、普通 get_profile 及 recall 统一过滤 deleted 字段；返回 profileInstanceId、profileTemplateId 和字段生成的记忆内容，满足现有标签投影。
- 模板同步及算法抽取更新必须保留字段状态，不得重新写入 value 时清除 deleted 标记；只有显式受控恢复才能重新激活。
- 恢复粒度为单个字段，保留原值及算法更新设置；账号、项目与普通记忆权限相同。画像不写 Qdrant，因此字段状态在单个实例文档中完成一致更新。
- 测试覆盖项目级多主体枚举、同字段 ID 稳定、单字段删除不影响其他字段、抽取不复活已删除字段、恢复、跨租户拒绝与重启持久化。

影响范围预期为 upstream 的请求模型、server_router 路由、生命周期服务及规则、ProfileService、普通读取/检索最终过滤、对应 tests/api 与导出的 OpenAPI。允许复用现有图/向量客户端确认写入，不默认改变所有 graph_db.update_node 调用方的错误语义。新增端点仅供可信控制面调用；原上游仍需限制在内网，不能将无鉴权的 8000 端口公开。

真实删除验收只针对新建的独立测试记忆，不删除已有环境验证记忆或用户数据。

## 审计日志和用量

- 初次完整导入，之后按文件标识、偏移增量读取；唯一键由来源文件代次及行位置确定，重启不重复计数。
- 处理轮转、截断、同名替换、半行追加、非法 JSON、缺字段；半行保留至下一次完成，坏行记录计数不导致所有页面失败。
- 解析 ts/tool/tenant/ms/ok/input/output 并保留原始关联信息；租户归属来自受控项目映射。
- tool 映射到 addMessage/searchMemory/getMemory/deleteMemory/addFeedback；不认识的事件不伪造为已知工具。
- 支持 source scope、主体、事件、状态、关键词、时间、分页；未知 eventType 按前端约定拒绝。
- SQLite 索引覆盖 tenant、ts、event、source、status；冷启动和已建索引两种场景均记录 1 万行首屏响应，不只测内存热缓存。
- 异步 add 按 callId 合并请求行和终态行，pending 耗时为 null，不重复计算实际调用次数。
- 用量复用同一份归一化审计索引，按天计数；全项目查询只覆盖当前账号有权访问的项目。
- token 缺失按 Issue 允许填 0，不凭文本长度推测；日界线、日期范围和空日期天行为在测试中固定。
