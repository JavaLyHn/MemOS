# 任务 04：P0 调用日志

范围：JSONL 增量导入、列表/详情、历史缺字段、来源与组合筛选、异步关联和 1 万行性能。当前任务不包含任务 05 的用量聚合。

## 实现

- `POST /api/dashboard/log/list` 返回 `{ code, data: { logs, total }, message }`；`POST /api/dashboard/log/detail` 返回同一日志 ID 的详情。失败统一返回非零业务码。
- 网关读取显式配置目录的 `calls-*.jsonl` 及数字后缀轮转文件（如 `.jsonl.1`）；备份、临时、压缩、协议 `requests-*`、检索诊断 `searches-*` 不作为调用计数。控制台仅对已交付的记忆列表、详情、删除、恢复、重试追加自己的 `console-*.jsonl`；查询日志不产生新调用日志。
- SQLite 保存文件物理标识、代次、已提交字节偏移及内容锚点；半行等待后续补全，坏行跳过并在 `audit_rejects` 保存代次/位置/原因（不保存原始坏行），文件记录与偏移在同一事务提交。支持追加、重命名轮转、同名替换、截断后重写超过旧偏移、进程重启和并发扫描。
- 文件是追加式审计源；内容锚点用于检测常见截断重写，不承诺识别任意原位修改。导入索引是可重建缓存，原 JSONL 才是权威数据。WAL `synchronous=NORMAL` 保持事务原子性，断电可能回退整个最近事务，随后重放；不能只提交偏移。
- 项目必须存在于受控映射。无租户的旧行不归入默认项目；用户 ID 不作为租户。详情契约只有 `logId`，因此使用实例固定默认项目，其他项目的 ID 返回 404。详情读已导入索引，列表请求刷新索引。
- `scope=all/gateway/console`，支持主体类型/ID、事件、状态、关键词、UTC 日期/带偏移时间戳和分页组合。关键词是脱敏后的事件、关联 ID、主体 ID、请求/响应正文的大小写无关字面子串；`%` 不是通配符。无主体 ID 时清空主体类型。未知事件原名展示，未知事件筛选值返回 400。
- 历史耗时缺失为 `null`、Token 缺失为 `0`、主体不猜测、时间缺失为空串、状态证据缺失为 `UNKNOWN`；正文缺失为 JSON 字符串 `null`。原本已编码的 JSON 字符串不二次编码；密钥脱敏，大正文标记截断。
- 异步按 `source + tenant + callId` 合并，支持终态先到、请求晚到、重复终态和跨项目/来源同名 ID。Pending 耗时为 `null`，一个逻辑调用只占一条列表记录。
- 矛盾字段中明确的业务失败优先于外层成功。终态缺少的信息不会覆盖已经确认的状态、耗时、Token 和正文；真实终态发生冲突时，较晚时间的明确证据优先，相同时间优先失败。明确报告的 0 Token 保留为 0。
- 审计正文捕获上限为 64 KiB；实际接口在 ASGI scope 独立记录已确认的项目和业务码，所以大请求不会丢失归属，大响应也不会因截断而把成功写成失败。凭据字段支持 snake_case、camelCase 和嵌套/已编码 JSON。

## 真实验收与边界

实际执行一次只读 MCP `search_memory`，用唯一标识在真实 `calls` JSONL 找到一行；列表和同 ID 详情的请求、响应正文、状态与耗时均与该原行相符。另一个项目查询此标识为 0 条。随后真实执行控制台记忆查询，产生独立 console 行，全部来源恰好两条。

验收页面为 [独立真实前端调用日志](http://127.0.0.1:5276/cn/requests)：关键词筛选两条、记忆调用来源筛选真实网关日志、详情显示唯一标识均通过。主前端 5274 保持 Mock；`src/`、`shared/`、`server/mock/` 和 `.env.local` 不改动。

当前网关本身只记录同步调用，没有 `callId` 和异步终态记录。异步合并使用独立 JSONL 夹具，经真实 HTTP 验证；没有把这部分宣称成生产网关异步联调。后续上游输出异步关联行时，需要显式 `callId`、请求/终态 phase 和 tenant。历史无关联 ID 的行不会被猜测合并。

真实验收脚本：`D:/MemOS/.venv/Scripts/python.exe D:/MemOS/setup/verify_task04.py`。只读现有记忆，调用一次真实检索；会消耗少量 embedding Token。报告 `D:/MemOS/.local/task04-runtime-verification.json` 只保存标识、ID、原文件定位、检查结果和计时，不保存密钥或完整真实正文。

## 性能

验收使用约 5.38 MB 的独立 1 万行 JSONL，每行包含主体、状态、耗时、Token 和约 300 字符响应内容。每轮使用全新 SQLite 数据库，首次真实 HTTP 请求包含建库、全部导入、SQL 查询和首屏序列化。不是预导入后的查询计时，也不代表冷操作系统文件缓存。

初次实现约 2.40 秒；性能分析后增加固定版本 `orjson==3.11.4`、SQLite 32 MiB 缓存，并减少无关联 ID 记录的重复存储。最终计时见本地报告与下表。

| 轮次 | 冷启动首屏 HTTP | 热查询 P50 / P95 | 重启后首屏 | 增量追加一行 |
|---|---:|---:|---:|---:|
| 1 | 903.312 ms | 27.431 / 31.335 ms | 53.558 ms | 37.823 ms |
| 2 | 859.519 ms | 26.070 / 31.443 ms | 37.083 ms | 34.467 ms |
| 3 | 893.486 ms | 27.619 / 31.166 ms | 39.996 ms | 43.239 ms |

冷导入原始文件为 **5,378,890 字节 / 10,000 行**，首屏 10 条响应约 **2,916 字节**。三轮均小于 1 秒。补充未负载运行的三轮为 805.607 / 793.371 / 755.036 ms；正式报告以上表为准。该指标受本机负载、磁盘和实际正文大小影响，不承诺任意大小的 1 万条正文均能在一秒内导入。

## 配置与复现

```powershell
$env:DASHBOARD_AUDIT_GATEWAY_DIR = 'D:/MemOS/.local/audit'
# 默认控制台目录为 DASHBOARD_DATA_DIR/audit；可选覆盖：
$env:DASHBOARD_AUDIT_CONSOLE_DIR = 'D:/MemOS/dashboard/.data/audit'
```

网关来源未配置、目录不存在或不可读时，查询该来源返回 503；明确存在且为空的目录才返回空列表成功。`console` 可独立查询。路径只接受进程配置，不接受 HTTP 参数。运行实例的启动配置变更必须重启自有后端进程，不替换其他占用端口的进程。

接口验证示例：

```powershell
$body = @{ projectId='issue3-project-a'; scope='gateway'; pageNum=1; pageSize=10 }
Invoke-RestMethod http://127.0.0.1:5281/api/dashboard/log/list -Method Post -ContentType 'application/json' -Body ($body | ConvertTo-Json)
```

控制台日志在业务响应后追加，写失败只记录异常类型，不把已经执行的操作变成可重试假失败。日志目录和索引应按审计数据设置本地权限。当前仍是单机 SQLite 方案；账号鉴权和多副本集中摄取不属于本任务。
